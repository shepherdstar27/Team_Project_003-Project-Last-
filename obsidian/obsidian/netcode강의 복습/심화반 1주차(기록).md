크게 3가지로 나뉨
	서버, 네트워크, 클라이언트

클라이언트의 역할
	입력(서버에게 보내는 것), 랜더링(서버로부터 받는 것)

서버의 역할
	판단(A가 B를 떄렸는가?), 
	동기화(판정결과를 접속한 이들 모두에게 동기화)
	모든 클라이언트의 정보 감시

네트워크
	서버와 클라이언트를 연결해주는 도로

핑
	서버와 클라이언트 사이를 왕복할 때 걸리는 시간


온라인 할떄, 클라이언트 끼리만 연결하면 되는데 왜 서버를 만드는가?
	둘만 있을 경우 교착상태가 발생할 수 있으므로 중재자를 두는 것

포톤퓨전은 크게3가지 모드로 구분됨

서버모드
	개념 
		포톤에서 대여하는 서버에 클라이언트가 접속하는 것
	장점
		안정적이며 공정함, 중간에 누가 나가더라도 게임이 꺼지지 않음
	단점
		비쌈
	
	배그 같은거 만들때 서버 모드를 사용

호스트 모드
    개념
		클라이언트 들 중에서 한명을 뽑아 서버로 만들어서 클라이언트를 관리
	장점
		무료
	단점
		호스트가 나가면 방이 터짐, 호스트의 환경이 게임에 큰 영향을 끼침

쉐어 모드
	개념
		모든 클라이언트가 서버처럼 기능함
	장점
		 개발하는데 있어서 네트워크 관련해 크게 신경 쓸 일이 줄어듬
		 개인 프로젝트 개발하듯 쉽게 개발할 수 있음
	단점
		보안에 취약함, 서로 교착상태에 빠지기 쉬움, 초기 설정이 귀찮음


유니티 네트워크 러너는 그냥 일반적인 유니티 스크립트가 아님

컴포넌트 자체가 하나의 게임 방이라고 생각하면 됨.
포톤 서버와 연결된 탯줄

서버에서 틱(Tick) 개념??(다시 찾아봐야 함)
	매 틱마다 플레이어의 입력을 수집하고 게임 상태를 시뮬레이션 하고 모든 클라이언트에게 전파하는 네트워크 루프 간격을 뜻함??

NetworkRunner의 기능
	세션의 통제권 : 게임의 시작과 종료를 전담
	Tick 관리 : 로컬게임에서는 프레임 단위로 고려하는게 맞는데 온라인게임에서는 틱을 고려해야 함
	틱 관리 : 매틱(매 프레임)마다 플레이어의 입력을 수집하고 게임 상태를 시뮬레이션 하면서 모든 클라이언트에게 전파하는 네트워크 루프를 실행
	호적관리 : 어떤 플레이어가 방에 들어왔고 나갔는가?
	물리적 실체를 부여 : 씬에 생성되는 캐릭터, 아이템 등등 단순한 유니티 오브젝트가 아닌 네트워크 오브젝트로 만들어 총괄 책임
