# DB 정리 노트 ③ — Port와 네트워크 기초

> **🔧 정정** = 잘못 이해한 부분, **➕ 보충** = 빠진 부분 (MySQL 설치 과정은 제외하고, 설치 때 마주치는 `3306`·`bind-address`·방화벽의 **원리**만 다룹니다)

---

## 1. Port란? — 노트의 정의 검증

> 노트: _"외부에서 실제로 송수신된 데이터들이 '올바른 프로그램'에 전달될 수 있도록 하는 충돌 방지 항구 역할"_

**앞부분은 정확합니다.** 이걸 네트워크 이론 용어로 부르면 **역다중화(Demultiplexing)** 입니다.

한 컴퓨터에는 IP 주소가 보통 **하나**인데, 그 안에서는 브라우저·게임·MySQL·Discord가 **동시에** 통신합니다. 패킷이 도착했을 때 "이건 누구 것이냐"를 가르는 기준이 **포트 번호**입니다.

### 계층으로 보면 포트의 위치가 명확해집니다

|계층|주소|무엇을 식별하나|
|---|---|---|
|2계층 (데이터링크)|**MAC 주소**|같은 네트워크 안의 **장비**|
|3계층 (네트워크)|**IP 주소**|인터넷상의 **호스트(컴퓨터)**|
|**4계층 (전송)**|**포트 번호**|그 호스트 안의 **프로세스(프로그램)**|

👉 **IP = 건물 주소, 포트 = 그 건물의 호실 번호.** 노트의 항구 비유도 좋지만(어원이 실제로 항구입니다), "몇 호실"이 실제 동작에 더 가깝습니다.

### 🔧 정정 1 — 포트는 "외부" 통신만을 위한 게 아닙니다

> 노트: _"**외부에서** 실제로 송수신된 데이터들이..."_

**같은 컴퓨터 안의 통신에도 포트를 씁니다.** MySQL 설치 직후 로컬에서 접속하는 것도 `127.0.0.1:3306` — 즉 포트를 통한 통신입니다.

```
[같은 PC 안]  내 앱  ──→  127.0.0.1:3306  ──→  MySQL 서버
[네트워크]    내 앱  ──→  10.0.1.50:3306  ──→  MySQL 서버(다른 머신)
```

포트는 **"호스트 내부에서 프로세스를 구분하는 번호"** 이고, 그게 외부에서 오든 내부에서 오든 똑같이 작동합니다. 이 구분이 뒤에 나오는 `bind-address`를 이해하는 데 결정적입니다.

### 🔧 정정 2 — "충돌 방지"의 정확한 의미

포트가 충돌을 막는다는 표현은 맞지만, 규칙을 정확히 알면 좋습니다.

> **하나의 (IP, 프로토콜, 포트) 조합은 한 프로세스만 리스닝할 수 있습니다.**

- 그래서 같은 머신에 MySQL 두 개를 띄우려면 `3306`, `3307`로 나눕니다
- 이미 점유된 포트를 잡으려 하면 `Address already in use` (EADDRINUSE) 에러 → **MySQL 설치 시 "3306 포트가 이미 사용 중" 에러의 원인**
- 단, **TCP 3306과 UDP 3306은 서로 다른 포트**입니다(아래 3장)

## 2. ➕ 보충 — IP + Port = 소켓(Socket)

> **소켓 = IP 주소 + 포트 번호.** 통신의 양 끝점을 가리키는 주소입니다.

```
클라이언트 192.168.0.10 : 51234   ←→   서버 10.0.1.50 : 3306
             (임시 포트)                    (고정 포트)
```

여기서 중요한 사실 하나:

> **서버는 고정 포트를 쓰지만, 클라이언트는 매번 임의의 포트를 받습니다.**

그래서 크롬 탭 10개로 같은 사이트에 접속해도 섞이지 않습니다. 실제로 OS가 연결을 구분하는 기준은 포트 하나가 아니라 **5-tuple** 입니다.

```
(프로토콜, 출발지 IP, 출발지 포트, 목적지 IP, 목적지 포트)
```

👉 노트의 "충돌 방지"가 실제로는 이 5-tuple로 보장됩니다. 그래서 서버는 **80 포트 하나로 수만 명**을 동시에 받을 수 있습니다. (클라이언트마다 출발지 포트가 다르므로)

## 3. ➕ 보충 — 포트 번호 체계

포트는 **16비트 정수** → **0 ~ 65535** (총 65,536개)

|범위|이름|용도|
|---|---|---|
|**0 ~ 1023**|Well-Known Port|표준 서비스. **바인딩에 관리자 권한 필요** (Linux)|
|**1024 ~ 49151**|Registered Port|특정 소프트웨어용으로 IANA에 등록 (**MySQL 3306**이 여기)|
|**49152 ~ 65535**|Dynamic / Ephemeral|클라이언트가 임시로 받아 쓰는 포트|

### ⚠️ TCP 포트와 UDP 포트는 완전히 별개의 공간입니다

이건 게임 서버 운영에서 실수하기 쉬운 지점입니다.

- `TCP 8211` 과 `UDP 8211` 은 **다른 포트**입니다
- 포트포워딩·방화벽 규칙을 만들 때 **프로토콜을 잘못 고르면 열었는데도 안 됩니다**
- 팰월드 데디 서버는 **UDP 8211** 입니다. TCP만 열면 접속이 안 됩니다

||TCP|UDP|
|---|---|---|
|연결|연결 지향 (3-way handshake)|비연결|
|신뢰성|순서 보장 + 유실 시 재전송|보장 없음 (빠름)|
|게임에서|**로그인, 과금, 채팅, DB, 웹**|**실시간 위치 동기화, FPS, 보이스**|
|DB|**항상 TCP** (MySQL 3306)|안 씀|

👉 DB는 데이터가 유실되면 안 되므로 **예외 없이 TCP**입니다.

## 5. 🔧 가장 중요한 정정 — "포트가 보안 역할을 수행한다"

> 노트: _"보안 역할도 수행함 (외부에서 함부로 특정 port의 프로그램에 접근할 수 없도록 통제도 가능 = 폐쇄된 항구)"_

**결론적 효과는 맞지만, 주체가 잘못되었습니다.**

> **포트는 그냥 숫자(주소)일 뿐, 스스로 아무것도 막지 않습니다.** 막는 주체는 **방화벽(Firewall)** 이고, 포트 번호는 방화벽이 **판단에 사용하는 기준(식별자)** 입니다.

주소가 보안을 하는 게 아니라, **문에 달린 자물쇠**가 보안을 합니다. 포트는 "몇 호실"이라는 번호이고, 방화벽이 "그 호실에는 아무도 못 들어간다"는 규칙입니다.

### "포트가 닫혀 있다"는 말의 세 가지 상태

|상태|실제 상황|접속 시 증상|
|---|---|---|
|**Open**|프로그램이 리스닝 중 + 방화벽 통과|정상 연결|
|**Closed**|**리스닝하는 프로그램이 없음**|즉시 거부 (`Connection refused`)|
|**Filtered**|프로그램은 있는데 **방화벽이 패킷을 버림**|응답 없이 대기 후 실패 (`Timeout`)|

👉 이 차이가 트러블슈팅의 핵심입니다. **`Connection refused` = 서버 프로그램이 안 떴다 / `Timeout` = 방화벽이 막았다.** MySQL 원격 접속이 안 될 때 이 둘을 구분하면 원인을 절반으로 줄입니다.

### 방화벽은 보통 두 겹입니다

노트의 데디 서버 이야기에서 "방화벽 해제 **와** 포트포워딩" 둘 다 필요했던 이유입니다.

```
인터넷
  │
  ├─ [ISP 차단] ────────── 일부 ISP가 특정 포트 차단 (드묾)
  │
  ├─ [공유기 / NAT] ────── ① 포트포워딩 규칙이 없으면 여기서 버려짐
  │
  └─ [OS 방화벽] ───────── ② Windows Defender Firewall 등에서 인바운드 허용
        │
        └─ [애플리케이션] ── ③ 프로그램이 리스닝하고 있고, 바인드 주소가 맞아야 함
```

**세 군데 중 하나라도 막혀 있으면 접속이 안 됩니다.** 그래서 "다 열었는데 왜 안 되지?"가 흔한 겁니다.

### ➕ 포트 번호를 바꾸는 건 보안이 아닙니다

MySQL을 `3306` 대신 `13306`으로 바꾸는 것은 **자동화된 스캐너의 노이즈를 줄이는 효과**는 있지만 **보안 대책이 아닙니다**. `nmap` 한 번이면 드러납니다. 이런 걸 **Security through Obscurity(숨김에 의한 보안)** 라고 하고, 진짜 방어는 아래 조합입니다.

1. **네트워크 차단** — 방화벽/보안그룹으로 필요한 출처만 허용
2. **인증** — 강한 비밀번호, 계정 분리
3. **인가** — 최소 권한 원칙 (노트 ②의 DCL)
4. **암호화** — TLS 연결
5. **감사** — 접속 로그

## 6. ➕ 보충 — 리스닝과 바인드 주소 (MySQL 보안의 핵심)

포트를 열 때 프로그램은 **"어느 IP로 들어오는 것을 받을지"** 도 함께 지정합니다. 이게 **바인드 주소(bind address)** 입니다.

|바인드 주소|의미|누가 접속 가능|
|---|---|---|
|`127.0.0.1` (localhost)|**루프백만**|**같은 컴퓨터 안의 프로그램만**|
|`10.0.1.50` (사설 IP)|그 사설망 인터페이스만|같은 내부망의 머신|
|`0.0.0.0`|**모든 인터페이스**|네트워크가 닿는 누구나|

MySQL 설정 파일(`my.ini` / `my.cnf`)의 이 한 줄이 그것입니다.

```ini
bind-address = 127.0.0.1    # 기본값(배포판에 따라). 외부 접속 원천 차단
# bind-address = 0.0.0.0    # ⚠️ 모두에게 개방
```

> 💡 이게 5장의 정정과 이어집니다. **포트를 "닫는" 방법이 방화벽 하나만 있는 게 아닙니다.** 애초에 `127.0.0.1`에만 바인드하면 방화벽 규칙이 없어도 외부에서는 도달할 방법이 없습니다. **가장 확실한 방어는 애초에 리스닝하지 않는 것입니다.**

## 7. ➕ 보충 — NAT와 포트포워딩은 왜 필요한가

노트가 **"포트포워딩을 한다"** 는 사실은 정확히 알고 있는데, **왜 해야 하는지**가 빠져 있습니다. 답은 **NAT** 입니다.

### 문제 상황

집에서 인터넷에 연결된 기기들은 **공인 IP를 공유합니다.**

```
인터넷 ←→ [공유기]  공인 IP: 123.45.67.89
              │
              ├─ 내 PC       192.168.0.10   ← 사설 IP
              ├─ 노트북      192.168.0.11
              └─ 스마트폰    192.168.0.12
```

**사설 IP 대역** (인터넷에서 라우팅되지 않는 주소):

- `10.0.0.0 ~ 10.255.255.255`
- `172.16.0.0 ~ 172.31.255.255`
- `192.168.0.0 ~ 192.168.255.255`

### 나갈 때는 문제가 없습니다

내가 웹서핑을 하면 공유기가 **NAT 테이블**에 기록을 남깁니다.

```
내 PC 192.168.0.10:51234  →  공유기가 123.45.67.89:60001 로 바꿔 보냄
                              ↓ NAT 테이블에 기록
응답이 123.45.67.89:60001 로 도착  →  "아, 이건 192.168.0.10:51234 것이구나"
```

### 문제는 **외부에서 먼저 들어오는 연결**입니다

친구가 `123.45.67.89:8211` 로 접속하면, 공유기는 **누구에게 줘야 할지 모릅니다.** NAT 테이블에 대응하는 기록이 없으니까요. 그래서 그냥 **버립니다.**

### 그래서 포트포워딩

공유기에 **"이 포트로 오는 건 이 사설 IP로 보내라"** 는 규칙을 **수동으로 미리 등록**하는 것입니다.

```
공유기 설정:  외부 UDP 8211  →  내부 192.168.0.10 : UDP 8211
```

> 📌 **정리: 포트포워딩은 보안을 푸는 작업이 아니라, NAT가 몰라서 버리는 인바운드 연결에 목적지를 알려주는 작업입니다.** 노트의 "폐쇄된 항구를 여는 것"보다는 **"항구에 '이 화물은 3번 창고로'라는 안내판을 붙이는 것"** 이 정확한 비유입니다.

### ➕ 실전 체크리스트 (데디 서버가 안 열릴 때)

1. **프로토콜 확인** — 팰월드는 **UDP**. TCP만 열면 안 됩니다
2. **사설 IP 고정** — DHCP로 IP가 바뀌면 포워딩 규칙이 엉뚱한 기기를 가리킵니다. 공유기에서 MAC 기반 IP 고정
3. **OS 방화벽** — 공유기만 열고 Windows 방화벽 인바운드 규칙을 안 만든 경우가 아주 흔합니다
4. **⚠️ CGNAT 확인** — 가장 흔한 실패 원인
    - 공유기 상태 화면의 공인 IP가 `10.x` / `100.64~127.x` / `172.16~31.x` / `192.168.x` 이면, **ISP가 또 한 번 NAT를 하고 있습니다**
    - 이 경우 **내 공유기에서 포트포워딩을 해도 소용없습니다** (ISP 쪽 라우터가 먼저 버림)
    - 확인: 외부에서 본 내 IP(포털에서 "내 IP 확인")와 공유기가 표시하는 공인 IP가 **다르면 CGNAT**
    - 해결: ISP에 고정IP/공인IP 요청, 또는 아래 대안
5. **대안**
    - **가상 LAN**: Tailscale, ZeroTier (요즘 가장 편함), Hamachi
    - **게임 자체 릴레이**: Steam Datagram Relay / P2P 호스팅 모드
    - **클라우드 VPS**: AWS/Vultr 등에 데디 서버를 올리면 NAT가 없어 포트만 열면 끝

## 8. ➕ 보충 — DB 관점에서 가장 중요한 결론

여기가 이 노트가 MySQL 설치로 이어지는 이유입니다.

### ⛔ MySQL의 3306 포트를 인터넷에 열지 마세요

노트의 "데디 서버 포트를 여는 것"과 **DB 포트를 여는 것은 위험도가 완전히 다릅니다.**

- `0.0.0.0:3306` + 포트포워딩을 하면, 몇 시간 안에 **자동화된 봇이 무작위 스캔으로 찾아내** 비밀번호 브루트포스를 시작합니다
- 뚫리면 데이터 유출·삭제·랜섬 요구까지 갑니다. MongoDB·Redis·Elasticsearch가 기본 설정으로 노출되어 대량 유출된 사건이 여러 번 있었습니다
- Redis(6379)는 기본 설정에서 **인증이 아예 없는** 경우가 있어 더 위험합니다

### ✅ 원격에서 DB를 써야 할 때의 정석

|방법|내용|
|---|---|
|**같은 서버에 두기**|앱과 DB가 한 머신이면 `bind-address = 127.0.0.1`. 포트를 아예 노출하지 않음|
|**사설망 안에서만**|앱 서버와 DB 서버를 같은 VPC/내부망에 두고, DB는 **사설 IP에만 바인드**|
|**방화벽/보안그룹으로 출처 제한**|AWS라면 RDS 보안그룹에서 **앱 서버의 보안그룹만** 3306 허용. IP 하나 단위로 좁힘|
|**SSH 터널링**|개발자가 로컬 DB 도구로 붙을 때. **3306은 안 열고 22번만** 사용|
|**VPN**|사내망에 붙은 뒤 내부 주소로 접속|
|**TLS 강제**|네트워크 구간 암호화|

SSH 터널 예시 — 내 PC의 13306을 원격 DB의 3306에 연결합니다.

```bash
ssh -L 13306:127.0.0.1:3306 user@db-server.example.com
# 이후 DB 도구에서 127.0.0.1:13306 으로 접속
```

### ⛔ 게임 클라이언트가 DB에 직접 붙어서는 안 됩니다

포트 이야기의 가장 실무적인 결론입니다.

```
❌ 게임 클라이언트 ──직접──→ MySQL:3306
   → DB 접속 정보(주소/계정/비밀번호)가 클라이언트 파일에 박힘
   → 디컴파일/메모리 덤프로 유출 → 유저가 DB를 직접 조작 (재화 무한 증식)

✅ 게임 클라이언트 ──HTTPS/TCP──→ 게임 서버(API) ──사설망──→ MySQL:3306
   → 클라이언트는 DB의 존재조차 모름. 검증·권한·트랜잭션은 모두 서버가 담당
```

이게 **3-Tier 아키텍처**(Presentation – Application – Data)이고, 노트 ①의 "DB에는 DBMS를 통해서만 접근(중앙집권)"이 네트워크 레벨에서 구현된 모습입니다.

## 9. ➕ 보충 — 포트 확인 명령어 (트러블슈팅)

### 내 컴퓨터에서 무엇이 어떤 포트를 쓰고 있나

```powershell
# Windows
netstat -ano | findstr :3306          # PID까지 표시
tasklist /FI "PID eq 1234"            # 그 PID가 어떤 프로그램인지
Get-NetTCPConnection -LocalPort 3306  # PowerShell
```

```bash
# Linux / macOS
ss -tlnp | grep 3306        # 리스닝 중인 TCP 포트 (요즘 표준)
lsof -i :3306               # 그 포트를 쓰는 프로세스
netstat -tlnp | grep 3306   # 구버전
```

> 출력의 **Local Address**를 보세요. `127.0.0.1:3306`이면 로컬 전용, `0.0.0.0:3306`이면 전체 개방입니다. 6장의 바인드 주소를 여기서 확인합니다.

### 상대 포트가 열려 있나

```powershell
# Windows (권장)
Test-NetConnection -ComputerName db.example.com -Port 3306
```

```bash
# Linux / macOS
nc -zv db.example.com 3306          # netcat
curl -v telnet://db.example.com:3306
nmap -p 3306 db.example.com         # 스캔 (⚠️ 남의 서버에 하면 불법일 수 있음)
```

|결과|해석|
|---|---|
|즉시 연결 성공|정상|
|`Connection refused`|서버에 도달했지만 **그 포트를 리스닝하는 프로그램이 없음** (서비스 미실행 / bind-address 불일치)|
|`Timeout` (응답 없음)|**방화벽·보안그룹·NAT가 패킷을 버림**|
|`Host unreachable`|라우팅/DNS 문제 (포트 이전 단계)|

### MySQL 설치 후 흔한 에러와 원인

|에러|원인|
|---|---|
|`Port 3306 already in use`|이전 MySQL 인스턴스나 다른 프로그램이 점유 → `netstat`으로 PID 찾아 종료, 또는 3307로 설치|
|`Can't connect to MySQL server (10061)`|서비스 미실행, 또는 포트/호스트 오타|
|`Host 'x.x.x.x' is not allowed to connect`|**포트 문제가 아닙니다.** MySQL 계정의 호스트 제한(`'user'@'localhost'`) 때문 → `'user'@'%'` 또는 특정 IP로 계정 생성 필요|
|원격에서 Timeout|`bind-address`가 127.0.0.1 / 방화벽 인바운드 / 클라우드 보안그룹|

> 마지막 항목이 중요합니다. **"접속 거부"에는 네트워크 계층(포트/방화벽) 문제와 DB 계정 권한 문제가 섞여 있습니다.** `Test-NetConnection`이 성공하는데 접속이 안 되면 네트워크는 정상이고 **계정·권한 문제**입니다.

## 10. 정리 & 면접 대비 Q&A

### 한 문단 요약

> 포트는 **전송 계층의 16비트 번호**로, 한 호스트 안에서 **어느 프로세스에게 데이터를 줄지 가르는 식별자(역다중화)** 입니다. IP와 합쳐 **소켓**이 되고, 실제 연결은 **5-tuple**로 구분됩니다. 포트 자체는 보안 기능이 없고, **방화벽이 포트 번호를 기준으로 차단**합니다. 외부에서 먼저 들어오는 연결은 **NAT가 목적지를 모르기 때문에** 공유기에 **포트포워딩** 규칙을 등록해야 도달하며, 프로그램이 **어느 IP에 바인드**했는지도 함께 맞아야 합니다. DB 포트(3306)는 이 모든 경로에서 **외부에 노출하지 않는 것이 원칙**이고, 원격 접근은 사설망·보안그룹·SSH 터널·VPN으로 해결합니다.

### 빈출 질문

|질문|핵심 답|
|---|---|
|포트란?|전송 계층(4계층)의 16비트 번호. 한 호스트 내에서 프로세스를 식별해 데이터를 올바른 프로그램에 전달(역다중화)|
|IP와 포트의 차이?|IP = 어느 컴퓨터(3계층), 포트 = 그 컴퓨터의 어느 프로그램(4계층). 합치면 소켓|
|포트 범위와 구분?|0~65535. Well-known(0~1023) / Registered(1024~49151) / Dynamic(49152~)|
|TCP 80과 UDP 80은 같은 포트?|**아닙니다.** TCP와 UDP는 별개의 포트 공간|
|서버는 포트 하나로 어떻게 수만 명을 받나?|연결 구분 기준이 5-tuple(프로토콜+양쪽 IP+양쪽 포트)이고, 클라이언트의 출발지 포트가 모두 다르기 때문|
|포트가 보안을 하나?|**아닙니다.** 포트는 번호일 뿐이고, 방화벽이 포트를 기준으로 차단합니다|
|`Connection refused`와 `Timeout`의 차이?|refused = 리스닝 프로그램 없음(닫힘) / timeout = 방화벽이 패킷을 버림(필터링)|
|포트포워딩은 왜 필요?|NAT 환경에서 인바운드 연결은 목적지 사설 IP를 알 수 없어 버려지므로, 공유기에 매핑 규칙을 수동 등록해야 함|
|포트포워딩을 했는데도 안 되는 이유?|프로토콜(TCP/UDP) 오선택, OS 방화벽 미허용, 사설 IP 변동, **CGNAT**, bind-address가 127.0.0.1|
|`0.0.0.0`과 `127.0.0.1` 바인드의 차이?|0.0.0.0 = 모든 인터페이스 개방 / 127.0.0.1 = 같은 머신에서만 접근 가능|
|MySQL 3306을 외부에 열면?|자동 스캐너가 곧 찾아내 브루트포스. 사설망·보안그룹·SSH 터널·VPN으로 대체|
|포트 번호를 바꾸면 안전한가?|스캔 노이즈만 줄 뿐 보안 대책이 아님(Security through Obscurity). 방화벽·인증·인가·암호화가 본질|
|게임 클라이언트가 DB에 직접 붙으면?|접속 정보가 클라이언트에서 유출되어 DB 직접 조작이 가능해짐. 반드시 게임 서버(API)를 경유하는 3-Tier 구조|
|게임이 UDP를 쓰는 이유?|재전송 대기보다 최신 상태가 중요(실시간 위치 동기화). 반대로 로그인·과금·DB는 유실이 안 되므로 TCP|
