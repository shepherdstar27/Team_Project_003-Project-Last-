## 코드 컨벤션 전체 정리 (최종 통합본)

### 1. 기술 스택 / 기본 방침

- **Addressables** + **UniTask** 사용
- 씬의 모든 것은 **프리팹으로 구성**, 동적 생성
- UI 텍스트는 **`TextMeshProUGUI`**, 버튼은 **`Button-TMP`**
- 써드파티 사용 전 **상업적 이용 가능 여부 확인** + 라이선스 화면 스크린샷 디스코드 공유

### 2. 네이밍

- 유니티 오브젝트 참조 필드: **`타입_이름`** → `Image_AAA`, `Prefab_AAA`, `Transform_AAA`
- 순수 데이터 private 필드: **`_카멜케이스`** → `_speed`
- 프로퍼티: **파스칼케이스**(첫 글자 대문자) → `SoundName { get; private set; }`
- 이벤트: **`On + 동사`** → `OnChangeCurrency`, `OnStartGame`
- 버튼 연결 메서드: **`OnClick + 동사`** → `OnClickBuild`
- 일반 메서드: **`동사 + 대상`** → `GetSize`, `ChangeName`, `MovePlayer`
- bool 반환 함수: 가능하면 **`Is` 접두어** → `IsAffordable`, `IsPlaceable` (단, `Try~` 동작 메서드는 예외)

### 3. 문법 규칙

- **람다 금지.** `ToDictionary(x => ...)` 같은 것도 `foreach`로 푼다.
    - **예외**: 뷰모델 프로퍼티의 `get => _field;`(표현식 본문)는 람다가 아니므로 허용 (팀 뷰모델 패턴)
- **제네릭 우선** (Array 대신 `List<T>` 등)
- 다른 사람이 쓸 확률 높은 메서드엔 **주석**
- 싱글톤 접근자는 **`.Inst`** (`.Instance` 아님)

### 4. 데이터 (JSON) 규칙

- 데이터 클래스는 **`GameData.cs` 한 파일에 몰아서** 작성
- **`GameDataBase` 상속** + `[Serializable]` + **public 필드**(프로퍼티 아님, JsonUtility 규칙)
- ID 필드는 **`ID`** (대문자 둘)
- JSON은 **최상위 배열**, 매니저가 `{"datas":...}`로 래핑해서 `JsonUtility`로 읽음
- enum은 JSON에 **문자열**로 저장 → 코드에서 변환 메서드로 파싱
- 조회는 **`GameDataManager.Inst.GetData<T>(id)`** 제네릭 창구로 통일
- 로드 등록은 `LoadAllData()`에 `LoadData<T>("테이블명")` 한 줄 추가
- JSON 경로: `Assets/Resources/JsonOutput/`
- `GameData.cs`는 **공용 파일**이라 수정 시 팀 협업 규칙 준수

### 5. MVVM 규칙

- 뷰모델은 **`ViewModelBase`** 상속 (`INotifyPropertyChanged` 기반)
- 뷰는 **`ViewBase`**(`MonoBehaviour`) 상속
- 모델은 따로 안 만들고 **뷰모델이 Model 역할 수렴**
- 서비스(순수 C#)가 뷰모델을 **`new` 생성·보관** → 뷰가 받아 바인딩
- 프로퍼티 변경 시 `OnPropertyChanged(nameof(프로퍼티))` 방송, setter에 `if (_field != value)` 검사

### 6. 폴더 구조

```
Assets/Scripts/
├── Manager/   (GameDataManager, BuildService, SingletonBase 등)
├── Data/      (GameData.cs, GridCoord, CellType, BuildGridData 등)
├── Object/    (GridSystem, BuildGridModel 등 순수 부품)
├── ViewModel/ (ViewModelBase, ViewBase, BuildGridViewModel)
└── UI/        (View 프리팹용 컴포넌트)
```

### 7. Git / 협업

- `master` 직접 push 금지, `feature/(기능)`에서 작업 → `develop`으로 PR
- 커밋 태그: `[feat]` `[fix]` `[chore]` `[refactor]`
- PR 제목: `[브랜치명(본인이름)] 기능 요약`, 작성 후 디스코드 공유, 본인이 직접 머지 금지
- 본인 작업물 외 파일 수정 시 해당 작업자에게 요청


### 7. 기타
